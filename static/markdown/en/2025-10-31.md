# tar xzvf file.tar.gz must go

<span class="text-red-800">Soy: This is an AI-translation of [this norwegian post](/blog/nb/2025-10-31).  </span>

I have some OPINIONS about unpacking archives with tar.

There are several (I found three, you could argue this is a thin basis) examples online that use these arguments: xzvf.

<img src="/static/tar_docker.png" alt="tar docker" width="400"/>

![nvim1](/static/tar_nvim.png)

<img src="/static/tar_taskwarrior.png" alt="tar taskwarrior" width="400"/>

First of all: Why would anyone want to fill the terminal with every single file and folder being unpacked? Tar will tell you if something goes wrong, there’s no reason to default to verbose output. Drop the -v!

Secondly: Twenty years ago, you might have had to tell tar which program to use for decompression, BUT look at this changelog from 2004:

> 2004-11-26  Sergey Poznyakoff  <gray@Mirddin.farlep.net>  
> ...  
> (open_archive): Autodetect compressed archives and act accordingly.  
> ...

Could it be that tar checks the magic bits and figures out the file type if you don’t specify it yourself?

I think so. I cloned the repo, read the C code, nodded to myself, stroked my beard, and thought: "Aah, I cannot C". Thank goodness for function names and comments.

In the diff between version 1.14 (11.05.2004) and 1.15 (20.12.2004), these functions were added in src/buffer.c:

```{git}

/* Check if the file FD is a compressed archive. FD is guaranteed to
   represent a local file */
enum compress_type
check_compressed_archive (int fd)

/* Open an archive named archive_name_array[0]. Detect if it is
   a compressed archive of known type and use corresponding decompression
   program if so */
int
open_compressed_archive ()
```

These are used in open_archive(), so you can skip the z too! Groundbreaking. Bold.

From now on:

```
tar xf file.tar.gz
```

Thank you.
