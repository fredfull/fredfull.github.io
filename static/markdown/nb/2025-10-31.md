# tar xzvf file.tar.gz må gå!

Jeg har noen MENINGER om å pakke ut arkiver med tar.

Det er flere (jeg fant tre, du kan argumentere for at dette er tynt grunnlag) eksempler på nettet som bruker disse argumentene: xzvf.

For det første: Hvorfor har man lyst til å fylle terminalen med samtlige filer og mapper som pakkes ut? Tar sier fra om noe går galt, det er ingen grunn til å defaulte til verbos output. Dropp -v!

For det andre: For tjue år sida måtte du kanskje si til tar hvilket program den skal dekomprimere med, MEN se på denne changeloggen fra 2004:


> 2004-11-26  Sergey Poznyakoff  <gray@Mirddin.farlep.net>  
> ...  
> 	(open_archive): Autodetect compressed archives and act accordingly.  
> ...


Kan det være at tar sjekker magic bits og skjønner filtypen dersom du ikke spesifiserer den selv?

Jeg synes det. Jeg har klona repoet, lest C-kode, nikket for meg selv og dratt meg i barten og tenkt: "Aah, jeg kan ikke C". Takk og lov for funksjonsnavn og kommentarer.

I diffen mellom versjon 1.14 (11.05.2004) og 1.15 (20.12.2004) har disse funksjonene blitt lagt til i src/buffer.c:
```{git}

/* Check if the file FD is a compressed archive. FD is guaranteed to
   represent a local file */
enum compress_type
check_compressed_archive (int fd)

/* Open an archive named archive_name_array[0]. Detect if it is
   a compressed archive of known type and use corresponding decompression
   program if so */
int
open_compressed_archive ()
```

Disse brukes i open_archive(), så du kan skippe z-en også! Grensesprengende. Modig.

Fra nå av:
```
tar xf file.tar.gz
```

Takk.
